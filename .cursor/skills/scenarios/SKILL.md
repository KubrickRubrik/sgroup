# Схема сценария

Syn3 запускает этот скилл дважды в режиме ask. Код фичи не менять. Файлы не писать. Форму вопросов не показывать.

Промпт содержит строку `Pass: questions` или `Pass: diagram`. Других проходов нет.

## Углы границ

Перед вопросами прочитать код этого сценария: экраны, каналы, хранилища. Угол только такой:

- где сценарий начинается и чем заканчивается
- какие входы входят, какие явно снаружи
- кто участники и где источник правды (файл, канал, хранилище)

Один вопрос — одна забота. Варианты конкретные и из этого репозитория. Не «Да/Нет», если развилка не бинарная. Не спрашивать сроки, раскатку, абьюз, «как бы я это написал». Варианта «упростить» нет.

## Pass: questions

Вернуть только один json-блок. Без схемы, без текста вокруг, без записи файла.

2 или 3 вопроса. У каждого минимум 2 варианта. `id` уникальны внутри ответа, `id` вариантов уникальны внутри вопроса.

```json
{"questions":[{"id":"start","prompt":"...","options":[{"id":"a","label":"..."}]}]}
```

## Pass: diagram

Границы уже выбраны в промпте. Новых вопросов нет. Ответ — markdown схемы. Первая строка ответа начинается с `#`.

Шаг, которого нет в коде или в выбранных границах, в схему не попадает. Несколько независимых входов, которые границы оставили внутри сценария, — несколько схем в одном ответе. Название чипа (`title:` из Discord) в заголовок не писать: заголовок — фича и сценарий из границ.

В ответе обязан быть рисунок последовательности: блок mermaid с `sequenceDiagram`.

## Каркас файла

```markdown
# <Фича>: <Сценарий>

<2–4 предложения: кто запускает, чем заканчивается, когда новое состояние видно.>

## Границы

- В сценарии: …
- Вне сценария: …

## Участники

| Участник на схеме | Где в коде |
|---|---|

## Последовательность

<Абзац, что схема показывает. Потом один или несколько блоков mermaid с подзаголовком на каждый вход.>
```

Язык файла — русский. Имена методов, каналов и ключей хранилища в тексте — как в коде, в обратных кавычках: `saveSkillIntoFolder`. Подпись стрелки — то же имя, без кавычек markdown.

## Визуал sequence-схемы

Схема читается по стрелкам и номерам. Цвет только отделяет роль и фазу, не раскрашивает каждый шаг.

Менять состав участников и порядок сообщений нельзя. Колонки идут в порядке первого появления. `box` только вокруг соседних участников одной роли, иначе Mermaid переставит колонки.

Стрелки: `->>` вызов, `-->>` ответ. `Note` — граница, которая не является вызовом (перезапуск, следующий старт). Заметка того же бумажного тона, что участник, без зелёной плашки. `autonumber` оставлять.

Имя колонки — короткая роль. Путь к файлу остаётся в таблице «Участники». Текст стрелки — действие как в коде. Длинную подпись разбить `<br/>`. Кегль 20px не уменьшать. Именованные цвета CSS (`OldLace`, `AliceBlue`, `HoneyDew`, `Cornsilk`) не использовать.

### Тема

Каждая схема начинается с этого init.

```mermaid
%%{init: {'theme': 'base', 'themeVariables': {'background': 'transparent', 'actorBkg': '#F7F6F4', 'actorBorder': '#C9C4BC', 'actorTextColor': '#292524', 'actorLineColor': '#E6E3DE', 'signalColor': '#57534E', 'signalTextColor': '#292524', 'noteBkgColor': '#F7F6F4', 'noteBorderColor': '#C9C4BC', 'noteTextColor': '#44403C', 'labelBoxBkgColor': '#F7F6F4', 'labelBoxBorderColor': '#C9C4BC', 'labelTextColor': '#44403C', 'activationBkgColor': '#EEECE8', 'activationBorderColor': '#C9C4BC', 'fontSize': '20px', 'actorFontSize': '20px', 'messageFontSize': '20px', 'noteFontSize': '20px', 'sequenceNumberColor': '#FFFFFF'}}}%%
```

### Рамки

Первое слово `box` — цвет, дальше подпись роли. Оттенок слабый: тёплый, холодный или серо-зелёный. Рядом роли различимы, по отдельности это почти бумага.

| Роль | box |
|---|---|
| Человек | `rgb(236, 230, 220)` |
| Flutter, экран, следующий Flutter-старт | `rgb(226, 231, 236)` |
| Натив | `rgb(226, 233, 228)` |
| Хранилище, если оно не внутри блока натива | `rgb(234, 230, 220)` |

### Полосы фаз

`rect` красит уже существующие сообщения, новых шагов не добавляет. Полоса бледнее рамки роли, чтобы стрелка оставалась главным. Над схемами одна легенда, если фаз больше одной:

- чтение — `rect rgb(236, 239, 242)`
- запись — `rect rgb(244, 239, 232)`
- момент, когда новое состояние начинает использоваться — `rect rgb(236, 242, 237)`

### Тёмные тона

Только если пользователь прямо просит тёмную схему. Состав сообщений тот же. Init заменить на:

```mermaid
%%{init: {'theme': 'dark', 'themeVariables': {'darkMode': true, 'background': '#161614', 'primaryColor': '#242320', 'primaryTextColor': '#F5F4F2', 'primaryBorderColor': '#6B6560', 'lineColor': '#6B6560', 'textColor': '#F5F4F2', 'actorBkg': '#242320', 'actorBorder': '#6B6560', 'actorTextColor': '#F5F4F2', 'actorLineColor': '#3A3835', 'signalColor': '#D6D3D1', 'signalTextColor': '#F5F4F2', 'noteBkgColor': '#242320', 'noteBorderColor': '#6B6560', 'noteTextColor': '#E7E5E4', 'labelBoxBkgColor': '#242320', 'labelBoxBorderColor': '#6B6560', 'labelTextColor': '#E7E5E4', 'activationBkgColor': '#2C2A28', 'activationBorderColor': '#6B6560', 'fontSize': '20px', 'actorFontSize': '20px', 'messageFontSize': '20px', 'noteFontSize': '20px', 'sequenceNumberColor': '#F5F4F2'}}}%%
```

Рамки: человек `rgb(54, 48, 42)`, Flutter `rgb(42, 48, 54)`, натив или следующий запуск `rgb(42, 50, 46)`, хранилище `rgb(52, 48, 42)`. Полосы: чтение `rgb(32, 36, 40)`, запись `rgb(42, 38, 34)`, применение `rgb(34, 42, 38)`.
