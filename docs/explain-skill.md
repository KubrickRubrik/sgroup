# Что делаем?

Объясни, что делает код. Файлы не меняй: ни правок, ни коммитов, ни пуша.

Скопируй этот файл в свой скилл. Путь к скиллу указывается в настройках Syn3 (активный профиль), поле «Путь к скиллу «Что делаем?»». Модель та же, что у ревью.

## Ответ

Весь ответ — markdown. Syn3 показывает его на чипе карты целиком.

Не пиши строку `H:N | M:N | S:N`. Её нет в этом скилле: чип не ждёт счётчики.

Язык — язык пользователя. Запуск от Syn3 — русский.

Структура:

1. Коротко, что меняется и зачем (2–4 предложения).
2. Что делает код: поток, входы и выходы по затронутым местам.
3. На что опирается: модули, контракты, данные. Только то, что видно в области.

Без патча, без ревью-замечаний и без списка «что улучшить». Не проси подтверждения.

## Запуск

Этот файл — весь скилл. Глубина и область приходят в том же сообщении. Глубину не переспрашивай. Не спрашивай то, что уже сказано.

| Команда | Глубина |
| --- | --- |
| `/rs` | поверхностное: дифф и ближайший контекст, что изменилось |
| `/rm` | среднее: дифф, вызывающий код и поведение, которого касается изменение |
| `/rd` | глубокое: поток данных, сбои, как части складываются |

Если команды `/rs`, `/rm` или `/rd` в запуске нет, глубина — medium.

Область бери из строки `Task:`:

- `Task: Что делаем? ветки` — вся ветка, которая войдёт в MR, без незакомиченного.
- `Task: Что делаем? изменений` — незакомиченные и незапушенные изменения.

К строке может быть добавлено `for merge request`. `Task:` важнее остальных слов, если в тексте встретились оба названия области.

Syn3 передаёт команду глубины и область в одном запуске. Вопросов не задавай и сразу пиши объяснение.

## Область

Только чтение git. Не переключай ветку.

Если в запуске есть блок `Host-diff` / `--- host-diff ---`, это вся область: объясняй только по нему. Локальный git и рабочее дерево не читай. Команды git не запускай.

**Ветка** — всё, что войдёт в MR, без незакомиченного:

1. Имя текущей ветки: `git branch --show-current`.
2. Родитель: строка reflog `branch: Created from <name>`, если такая ветка есть. Иначе локальная ветка, чей tip совпадает с `git merge-base HEAD <branch>` и у которой минимальный `git rev-list --count <branch>..HEAD`. Иначе `origin/development`, `origin/main`, `origin/master` — первая существующая.
3. `git diff <parent>...HEAD` и `git log --oneline <parent>..HEAD`.

**Изменения** — то, чего ещё нет на удалённой ветке:

1. Незакомиченные: `git diff HEAD` (индекс и рабочее дерево).
2. Незапушенные коммиты: если есть `@{upstream}`, то `git diff @{upstream}...HEAD` и `git log --oneline @{upstream}..HEAD`. Если upstream нет, незапушенных коммитов не выдумывай и не подменяй их всей веткой: объясни только незакомиченное и одной фразой скажи, что upstream не настроен.

Пустой дифф — это результат. Напиши одну фразу, что смотреть нечего. Строку важности не добавляй.
