# Скилл тега Figma

Путь к этому файлу указан в настройках карты Figma, поле «Путь к скиллу». Рядом лежит `lookup.js`. Это единственный скрипт поиска.

Файлы не меняй. В Figma ничего не пиши: ни `setPluginData`, ни `setSharedPluginData`.

## Вход

Тег берёшь из запроса пользователя. Это одна строка, как её сохранил JSON Metadata Tagger.

Ссылки лежат у страницы Figma в Syn3, поле `figmaFiles` в `.syn3/base.json` (страница с `"kind": "figma"`). Элемент — строка-ссылка или объект `{ "url", "label" }`. `url` — ссылка, не голый ключ. Голый ключ читай как ссылку на весь файл. `label` — подпись, которую ввёл человек, чтобы узнать узел. На область поиска она не влияет.

Из ссылки возьми ключ файла (сегмент после `/design/` или `/file/`; у ветки — ключ после `/branch/`) и `node-id`. В id дефис замени на двоеточие.

Область поиска — сама ссылка:

- нет `node-id` — весь файл, все его страницы (`Файл/*`);
- `node-id` страницы (`type === "PAGE"`) — только эта страница, `ROOT_ID` пустой (`Файл/Страница/*`);
- `node-id` слоя — страница этого слоя в `PAGE_ID`, сам слой в `ROOT_ID` (`Файл/Страница/Слой/*`).

Если ссылок несколько, обойди каждую в её области. Токен Figma не читай и не печатай.

## Как искать

Перед `use_figma` открой скилл figma-use. На первый файл вызови `create_session` и дальше передавай его `sessionId`. В `skillNames` укажи `figma-use`.

Для ссылки с `node-id` сначала узнай тип узла, без обхода слоёв:

```js
const node = await figma.getNodeByIdAsync("NODE_ID");
let page = node;
while (page && page.type !== "PAGE") page = page.parent;
return {
  found: Boolean(node),
  type: node && node.type,
  pageId: page && page.id,
  name: node && node.name,
};
```

Дальше один вызов `lookup.js` из каталога этого скилла. В коде одна смена страницы. Подставь четыре константы:

- `TAG_VALUE` — тег. Кавычки и обратные слэши заэкранируй. Меняй только эту константу.
- `FILE_KEY_VALUE` — ключ файла. Меняй только эту константу.
- `PAGE_ID_VALUE` — id страницы. Для страницы это её id, для слоя — id страницы-родителя.
- `ROOT_ID` — пустая строка для файла и страницы. Для слоя подставь его id.

У слоя без детей `findAll` нет: не запускай обход, прочитай тег одним `getSharedPluginData("icon_tagger", "tags")` с этого узла.

Для ссылки без `node-id` сначала список страниц, без обхода слоёв:

```js
const pages = figma.root.children.map((page) => ({ id: page.id, name: page.name }));
return { fileName: figma.root.name, pages };
```

Затем на каждую страницу — один параллельный вызов `lookup.js` с пустым `ROOT_ID`.

Если вызов страницы оборвался по времени, переключись на неё отдельно, верни id верхних детей и повтори скрипт по одному ребёнку: в `ROOT_ID` подставь id этого ребёнка. Страницу в каждом вызове меняй один раз.

Тег лежит только в `getSharedPluginData("icon_tagger", "tags")`. `get_metadata`, `get_design_context` и `get_screenshot` его не отдают. Приватный `getPluginData` в этом MCP закрыт.

## Ответ

Язык — русский. На каждую найденную сущность:

- имя и тип слоя
- ссылка из поля `link`
- дата создания, обновления и редактирования — только те поля, где строка не пустая

Пустую дату не заполняй и не выводи. Если у сущности все три даты пустые, напиши, что дат создания, обновления и редактирования у слоя нет. `fileUpdatedAt` — это дата файла целиком, не слоя: упоминай её отдельно и только если она не пустая.

Если совпадений нет, так и напиши: тег на обойдённых страницах не найден. Не подставляй другой слой.
